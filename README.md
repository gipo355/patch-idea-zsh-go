# patch-jetbrains-ide

> ⚠ **Linux only.** Requires [JetBrains Toolbox](https://www.jetbrains.com/toolbox-app/).

Small CLI that patches the JetBrains **`.desktop` launcher files** so the IDE is
started through your shell and inherits your shell environment (PATH, and the
shims injected by version managers like `mise`, `asdf`, `nvm`, `pyenv`, SDKMAN, …).

## Installation

```bash
go install github.com/gipo355/patch-jetbrains-ide@latest
```

Requires Go 1.23+. Linux only — the tool works on XDG `.desktop` files
(`~/.local/share/applications`), which don't exist on macOS or Windows.

## Why this is needed

Apps launched from the **GUI** (application menu, dock, "Open Folder with…") are
started by the desktop environment, **not** by your terminal. They therefore do
**not** source `~/.zshrc` / `~/.bashrc`, so none of the PATH entries or tool shims
you set up there are visible inside the IDE — its built-in terminal, run
configurations, and toolchain detection all see a bare system PATH.

This tool rewrites the desktop file's `Exec=` line from:

```ini
Exec="/…/Toolbox/apps/intellij-idea-ultimate/bin/idea" %u
```

into:

```ini
Exec=/usr/bin/zsh -i -c "/…/Toolbox/apps/intellij-idea-ultimate/bin/idea" %u
```

so an **interactive** shell (`-i`) is started first, your rc file runs, and the
IDE then launches with the resulting environment. The original line (and the rest
of the file) is preserved, commented out, under a `# patched on <date>` marker so
you can always revert by hand.

> **Note on quoting:** the IDE path is wrapped in a single pair of *literal*
> double quotes with no escaping. GLib-based launchers (`gio`, `gtk-launch`, most
> GNOME/file-manager launches) **refuse to load** a `.desktop` file whose `Exec`
> line contains nested or escaped quotes, so more elaborate wrappers (e.g. adding
> `exec` or forwarding `"$@"`) silently break launching. The simple form is
> deliberate.

## Two different launchers — don't confuse them

JetBrains Toolbox generates **two** separate things, and this tool only touches
the first:

| What | Where | Used when | Patched here? |
| --- | --- | --- | --- |
| **Desktop files** | `~/.local/share/applications/jetbrains-*.desktop` | You launch from the app menu / dock / "Open with" | ✅ yes |
| **Shell scripts** | `~/.local/share/JetBrains/Toolbox/scripts/{idea,goland,…}` | You type `idea .` in a terminal | ❌ no |

The shell scripts are the ones enabled by **Toolbox → Settings → Tools →
"Generate shell scripts"**. They are plain wrappers, e.g.:

```bash
#!/bin/bash
#Generated by JetBrains Toolbox …
"/…/Toolbox/apps/intellij-idea-ultimate/bin/idea" "$@"
```

When run from a terminal you already have your shell environment, so these do
**not** need the env-inheritance patch.

## FAQ

**Do the `idea`, `goland`, … commands come from Toolbox?**
Yes. Toolbox → Settings → Tools → **Generate shell scripts** creates them in the
configured *Shell scripts location* (default
`~/.local/share/JetBrains/Toolbox/scripts`), which you add to your `PATH`.

**Why does `idea .` lock my terminal, when `code .` (or `webstorm .`) doesn't?**
The Toolbox scripts are all identical in shape (`"…/bin/<name>" "$@"`, foreground),
so the difference is in the **IDE launcher itself**. IntelliJ IDEA Ultimate starts
a JCEF/Chromium subprocess at launch (its AI/web features — the `Starting cer
server` + `DevTools listening on ws://…` lines) and keeps that child's stdio wired
to your terminal, so the shell stays bound. Lighter IDEs (WebStorm, GoLand,
DataGrip) don't start it, so they return immediately.

The fix is to detach the launch. Run `patch-jetbrains-ide --wrappers` (see below),
or add a wrapper to your shell rc by hand:

```zsh
idea() { (nohup "$HOME/.local/share/JetBrains/Toolbox/scripts/idea" "$@" >/dev/null 2>&1 &) }
```

(or just `nohup idea . &` ad hoc). This is a terminal-launcher concern, separate
from the desktop-file patching.

**What are the `SLF4J(E)/(W)` messages?**
Harmless logging noise from the IDE's bundled SLF4J setup — not an error you
caused. They only show up because the launch is attached to your terminal;
detaching the process (above) hides them.

## Flags

| Flag | Short | Description |
| --- | --- | --- |
| `--help` | `-h` | Show help |
| `--dry-run` | `-d` | Print the patched output without writing |
| `--all-ides` | `-a` | Select all IDEs (no prompt) |
| `--all-files` | `-y` | Select all matching files (no prompt) |
| `--repatch` | `-r` | Re-patch / overwrite existing patches and wrappers |
| `--current-shell` | `-c` | Use the shell from `$SHELL` (no prompt) |
| `--wrappers` | `-w` | Also generate detaching terminal wrappers (see below) |
| `--wrappers-only` | | Only generate wrappers, skip desktop patching |
| `--wrapper-dir` | | Target dir for wrappers (default `~/.local/bin`) |

## Examples

Interactive:

```bash
patch-jetbrains-ide
```

Patch everything non-interactively using `$SHELL`:

```bash
patch-jetbrains-ide -acyr
```

Preview without writing:

```bash
patch-jetbrains-ide -ad
```

## Freeing the terminal (`idea .`, `webstorm .`, …)

Separate from desktop patching, `--wrappers` generates a small detaching wrapper
in `~/.local/bin` for every Toolbox launcher, so `idea .` returns immediately and
doesn't stream the IDE's logs to your shell (like `code .`):

```bash
patch-jetbrains-ide -acyrw            # patch desktop files AND generate wrappers
patch-jetbrains-ide --wrappers-only   # only the wrappers, no desktop patching
patch-jetbrains-ide --wrappers-only -d # preview only
```

Each wrapper just runs the real Toolbox script detached:

```sh
#!/bin/sh
nohup "$HOME/.local/share/JetBrains/Toolbox/scripts/idea" "$@" >/dev/null 2>&1 &
```

For this to take effect, the target dir must come **before** the Toolbox scripts
dir on your `PATH` (the tool warns if it doesn't). Wrappers survive Toolbox
regenerating its scripts, and a re-run only overwrites files it generated (pass
`-r` to overwrite unrelated files).
